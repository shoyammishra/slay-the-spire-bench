## Part 1 — The review (content preserved verbatim)

### Executive Summary

This is substantially stronger than the version you showed months ago. However, if I
were reviewing for NeurIPS Datasets & Benchmarks, I would still reject it today. Not
because it is bad. Because it still lacks one piece of evidence that turns the core
hypothesis from interesting observation into general scientific result. The missing
frontier-model experiment is not "nice to have." It is probably the experiment
determining acceptance.

### STEP 1 — Reconstructing the Intended Contribution

The paper is not trying to build another game benchmark. The actual scientific question
appears to be: *Existing planning benchmarks evaluate planning at one temporal scale.
Can planning ability instead be decomposed into nested horizons, revealing where
planning begins to fail?*

The proposed contribution is roughly:
- Build a deterministic Slay the Spire simulator.
- Decompose planning into four horizons.
- Design different oracles for each horizon.
- Evaluate identical models under identical seeds.
- Produce a "planning horizon profile" instead of a single scalar score.
- Show that different models fail at different horizons.

The implicit scientific claims are:
- Planning is multidimensional rather than scalar.
- Aggregate game scores hide meaningful capability differences.
- Planning collapse occurs gradually rather than abruptly.
- Model capability shifts the collapse point.
- Representation (JSON vs English) matters differently across horizons.

That reconstruction is internally consistent.

### STEP 2 — Novelty

This is where reviewers will spend the most time.

**Closest existing work (very close):** PlanBench, TravelPlanner, NaturalPlan,
SmartPlay, DSGBench, Orak, Bateni & Whitehead MiniSTS, GameBench, LLM Chess
evaluations, GraphArena, CO-Bench. You correctly position against most of these.
That helps.

**Strong novelty:**
- Using one domain while varying planning horizon instead of varying domains.
- Per-horizon oracle design (probably the strongest contribution).
- Planning horizon curve (interesting and potentially memorable if validated).

**Moderate novelty:**
- JSON vs English (useful but not publication-driving).
- Optimality-relative normalization (useful engineering, not novel).
- Simulator (necessary infrastructure, not itself novel).

**Weak novelty:**
- Using Slay the Spire (already established).
- Game benchmark (many already exist).

**Reviewer probability of saying "This has already been done": 45%.** Half the
reviewers will initially think "Another game benchmark." The positioning must prevent
this.

### STEP 3 — Contribution Analysis

Architecture: Absent. Evaluation protocol: Strong. Scientific insight: Moderate.
Systems contribution: Moderate.

This is primarily an **evaluation methodology paper**, not an algorithm paper.

### STEP 4 — Impact

Academic impact: potentially good. Industrial impact: moderate — OpenAI/Anthropic
probably would not directly use the benchmark without evidence it predicts real-agent
capability. **That's a major issue.** Potential citations: 30–80 if accepted; 100–300+
if frontier-model validation becomes compelling. Will it change the field? Today:
probably not. With stronger validation: possibly.

### STEP 5 — Experimental Review

This is where the strongest criticism lies.

- **Missing frontier models — huge issue.** The report itself admits this. Without
  GPT-5/Claude/Gemini-level models: how do we know the observed curve isn't simply
  "small models are weak"?
- **Single environment.** Only one game. Can conclusions generalize? No evidence.
- **Oracle validity.** Turn oracle: excellent. Combat oracle: reasonable. Synergy
  oracle: expert labels — potential concern. Run oracle: weakest.
- **Missing correlation analysis.** The paper argues planning horizon predicts
  capability. Show it. Need correlation against: SWE-Bench, OSWorld, WebArena, GAIA,
  BrowseComp, AgentBench. Without this: why should anyone care?
- **Statistical concerns.** Need: confidence intervals, bootstrap analysis, effect
  sizes, hypothesis testing, variance decomposition. Not just averages.
- **Missing ablations.** Need: oracle removal, horizon removal, different seed
  distributions, different game acts, different prompt lengths, CoT vs no CoT,
  memory vs no memory, tools vs no tools.

### STEP 8 — Hidden Weaknesses

1. **Planning horizon may simply measure task difficulty, not planning.** Need
   evidence separating these.
2. **Run-level failures may arise from context accumulation rather than planning.**
   Different phenomenon.
3. **Different horizons use different metrics.** Can they really be compared?
   Reviewer concern.
4. **Single-game inductive bias.** Maybe Slay the Spire uniquely behaves this way.
5. **Per-horizon oracle quality differs.** Turn: exact. Synergy: human. Run: baseline.
   That inconsistency weakens comparisons.

### STEP 13 — Final Verdict

Overall 6.6/10 · top 30–40% of submissions · best fit NeurIPS D&B, then TMLR and
AAAI · **Weak Reject** · confidence ~0.82.

**Area Chair summary:** carefully engineered benchmark decomposing planning into
nested horizons within a single deterministic environment; benchmark design,
simulator, reproducibility are strengths. However, the central scientific claims are
supported only in one environment, primarily on open models, without demonstrating
that the planning-horizon measure generalizes across domains or predicts broader
agent capability. Requires stronger empirical validation — particularly
frontier-model evaluation and external correlation studies.

**Bottom line:** the core idea — isolating planning horizons within a single domain —
is the part with real promise. The evidence currently supports "this phenomenon
exists in this benchmark," NOT "this is a general property of LLM planning." Closing
that gap with frontier-model results and cross-benchmark validation would move the
work significantly closer to a competitive NeurIPS D&B submission.

### 2.3 Miscalibrated or missing evidence we already hold

Three "hidden weaknesses" have partial or full on-disk answers the reviewer could not
have seen. Each becomes a named argument in the paper (P6 scope):

1. **"Horizon may just measure difficulty."** Counter-evidence = the *dissociation*
   pattern: deepseek-7b collapses on execution (combat win .14–.28) while its synergy
   removal is 2nd-best in the matrix (.54 IC structured); qwen3-32b bends away *only*
   at synergy. A monotone difficulty axis cannot produce crossing per-model orderings.
   (Caveat travels: deepseek-7b synergy conditioned on parse_ok .69–.92.)
2. **"Run-level failure may be context accumulation."** The harness is deliberately
   memoryless — every call is a fresh serialization of current state; no transcript
   grows across the run; prompt size is bounded by deck/relic count, not run length.
   Run-level collapse cannot be context-window exhaustion. One-paragraph rebuttal;
   also strengthens the floor-vs-ceiling complement framing vs Anthropic's scaffolded
   agent.
3. **"No theory of why horizons differ."** We will not produce theory, but the parse
   probe's registered causal verdict (budget-bound deliberation as the *cause* of the
   distills' long-horizon collapse, 2026-07-13) is a mechanistic account for one
   family — more than most benchmark papers offer. Promote from diagnostics footnote
   to first-class mechanism finding.

**Pushback (documented scope-out, not a gap):** the memory ablation on the wishlist
conflicts with the design — memory breaks per-horizon oracle determinism, was excluded
deliberately, and the Fable 5 STS eval is cited as the memory-ceiling complement. The
paper must say this explicitly (a defensible "no").

### 2.4 Newly actionable, ranked by cost

1. **Statistical rigor pass — zero GPU, highest ROI-per-cost.** Per-sample records
   already persist (2,400 synergy samples; `turn.samples[]`/`combat.samples[]` since
   2026-07-13). Compute bootstrap CIs, effect sizes, and — critically — **paired
   tests for the format ablation**: the seed-matched design was built for paired
   testing and the test has never been run. Pure analysis on the 24 on-disk
   aggregates + per-seed files. → new backlog row 4b.
2. **Three rebuttal paragraphs + claim-scoping pass** (§2.3 above) → folded into P6
   scope.
3. **Cross-benchmark correlation piggybacks on M3b.** Do not run SWE-Bench etc.
   ourselves — once frontier models are in our matrix, correlate their *published*
   GAIA/SWE-Bench/WebArena scores against our per-model collapse points. n≈8–10
   models → underpowered, report as directional, but it directly answers Reviewer D.
   → added to M3b fold-in scope.
4. **Cheap ablation additions** (post-M3b, cluster): explicit CoT-prompt ablation on
   one instruct model (the reasoning-vs-instruct contrast is currently only a
   quasi-ablation); synergy oracle sensitivity (perturb expert labels / second rater
   on the 40 fixtures — analysis-mostly).
5. **Second environment — genuinely expensive; explicitly deferred.** The method-not-
   artifact reframing + candidate-game list (Monster Train, Into the Breach, NetHack)
   already exists in `novelty_and_related_work.md`. Realistically post-M3b or a
   follow-up paper. TMLR is the honest fallback if it never happens.

### 2.5 Where I disagree (recorded so it isn't re-litigated)

- Citation-count and impact projections are noise; ignore for planning.
- "Tools vs no tools" ablation is out of scope for a raw-planning-floor instrument —
