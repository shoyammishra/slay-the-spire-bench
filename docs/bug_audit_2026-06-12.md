## C — CRASH

### C1. Playing Sentinel crashes the engine (VERIFIED)
`cards.py:1316` references `PowerId.SENTINEL`, which **does not exist** in `enums.py`
→ `AttributeError` the moment Sentinel is played. Sentinel is in the Ironclad
UNCOMMON reward pool, so any run-level game that drafts and plays it kills the whole
benchmark invocation (only `RateLimitExhausted` is caught — completed work in that
process is lost). A full phantom-enum scan found no other missing members.
**Fix:** implement the real card — "If this card is exhausted, gain 2 (3) Energy":
drop the power grant entirely; in `powers.py` `on_exhaust`, if the exhausted card is
a Sentinel, `player.energy += 3 if card.upgraded else 2`. Regression test: play
Sentinel (no crash, block only), exhaust a Sentinel (energy gained).

## E — ENGINE

### E1. Berserk energy gated on being Vulnerable (dead after 2 turns)
`powers.py:39`: `if player.berserk and PowerId.VULNERABLE in player.powers` — real
Berserk gives +1 energy at the start of EVERY turn unconditionally (the self-
Vulnerable 2 (1 upgraded) is just the upfront cost). As written the card pays its
cost and then stops working when Vulnerable expires.
**Fix:** `if player.berserk: player.energy += 1`.

### E2. Brutality flag never reset → permanent across the run
`end_combat()` (`combat.py:450-454`) resets `barricade`/`berserk`/`corruption` but
NOT `brutality`; `start_combat()` doesn't either. One Brutality play = lose 1 HP +
draw 1 every turn in every later combat of the run.
**Fix:** reset `state.player.brutality = False` in `end_combat` (and defensively in
`start_combat`).

### E3. Brutality+ "Innate" is dead code
`Brutality.play` sets `state.player.innate_brutality` (`cards.py:1451`) which is
never read anywhere. Real Brutality+ is **Innate** (a property of the card).
**Fix:** constructor `innate=upgraded`; `upgrade()` sets `self.innate = True`;
delete the dead `innate_brutality` field from `state.py` and the write in cards.py.

### E4. Enemy INTANGIBLE never ticks → Awakened One becomes permanently unkillable
Enemy debuff ticking covers only WEAK/VULNERABLE (`combat.py:378`); INTANGIBLE on
enemies never decrements. Nemesis works around it manually (deletes at phase 3);
Transient escapes anyway; but **Awakened One's "Rebirth" move
(`enemies_act2.py:798`) sets INTANGIBLE=1 permanently** → from its 4th turn on, the
Act-3 boss takes ≤1 damage per hit forever (Act-3 run-level = guaranteed loss/draw).
**Fix:** tick enemy INTANGIBLE down at end of round in `_tick_enemy_powers`; make
Nemesis re-apply INTANGIBLE=1 each `select_move` while `_phase < 3` and Transient
re-apply each turn (preserves their intended phases); Awakened One's Rebirth then
correctly grants 1 round of Intangible.

### E5. Pride curse: wrong mechanic + greedy-bot energy drain
`Pride.play` (`cards.py:483-485`) adds a fresh copy **to hand** on play. Real Pride:
Innate, playable+exhaust, and at END of turn puts a copy **on top of the draw
pile** (only while in hand). As written, the greedy bot (which plays every playable
card) replays Pride every turn forever, wasting 1 energy per loop iteration.
**Fix:** `play` = exhaust only (no copy); add `end_of_turn_effect` that appends a
copy to the top of the draw pile (the `on_turn_end` hand iteration already calls
`end_of_turn_effect`).

### E6. Sentry Artifact 0 (real: 1); Lagavulin dead ARTIFACT key
`enemies.py:560` Sentry sets `ARTIFACT = 0` (no-op; real Sentries have Artifact 1).
`enemies.py:515` Lagavulin sets `ARTIFACT = 0` (real Lagavulin has none — dead key).
**Fix:** Sentry → 1; delete the Lagavulin line.

### E7. Structured prompt leaks zero-valued enemy powers (format asymmetry)
`_enemy_summary` (`prompt_builder.py:47-48`) does not filter falsy power values —
"Artifact: 0" etc. appear in structured prompts, while the raw format AND the player
summary both filter `if v`. Noise + a small uncontrolled structured-vs-raw asymmetry.
**Fix:** filter falsy values in `_enemy_summary` like the other two sites.

### E8. Duplicate relic classes double-weight rarity pools (VERIFIED)
`FULL_RELIC_LIST` (`relics_full.py:1032-1058`) lists HandDrill twice (uncommon +
shop sections) and BustedCrown/EmptyCage/SacredBark/Sozu/VelvetChoker twice (rare
section + boss section). `_RARITY_POOLS` filters that list, so: **uncommon pool has
HandDrill ×2, shop pool HandDrill ×2** (double drop probability), boss pool has 5
doubled entries (path mostly unused — boss choices use `BOSS_RELIC_POOL` strings).
**Fix:** dedupe `FULL_RELIC_LIST` (remove the repeated mentions; registry/pool sets
already encode rarity membership).

### E9. Relic block bypasses BLOCK_GAINED (Juggernaut never triggers)
Orichalcum (`relics_full.py:141`), Captain's Wheel (`:525`), Cloak Clasp (`:534`) do
`player.block +=` directly. In real StS these trigger Juggernaut.
**Fix:** keep the flat block (relic block must NOT get Dex/Frail, so don't use
`_gain_block`) but emit `Event.BLOCK_GAINED` with the amount.

### E10. Identity-invariant violation at combat start (latent)
`start_combat` moves innate cards with equality-based `draw_pile.remove(c)`
(`combat.py:38`) — the exact pattern three audits banned. Currently benign (twins
are interchangeable at combat start) but fragile.
**Fix:** use `_remove_identical`.

### E11. `Player.cards_played_this_combat` is write-only and never reset
Incremented in `play_card` (`combat.py:207`), never read, never reset (accumulates
across the run). Dead + misleading next to the real per-combat counter on
`CombatState`. **Fix:** delete the field and the increment.

### E12. Empty Cage doesn't count its removals
`EmptyCage.on_pickup` removes 2 cards without bumping `_cards_removed` (the Winged
Statue "per card removed this run" counter that shops/Peace Pipe/events maintain).
**Fix:** increment by 2.

## H — HARNESS / INSTRUMENT (synergy first)

### H1. Synergy fixture ironclad#16: self-contradictory ground truth
Fixture index 15 (5th Aggro deck): expert **pick = "Perfected Strike"** while expert
**removal = "Strike"** — Strikes feed Perfected Strike, so a model that takes the
pick and then refuses to remove Strike is being logically consistent yet scored
wrong on removal. This is exactly the ambiguity class that got Perfected Strike
purged from the 4 Aggro DECKS in the 2026-06-11 batch (item 2.8) — the OFFER slot
was missed.
**Fix:** replace the offer "Perfected Strike" → "Twin Strike" (Aggro-listed, same
pattern as fixtures 4 and 20; other offers Iron Wave/Defend stay off-archetype, so
`test_synergy_fixture_ground_truth_rules` still passes). Aggregates remain
comparable; the synergy re-run regenerates rows anyway.

### H2. Negative `target_index` silently targets the LAST enemy
`CombatEvaluator` (`benchmark.py:530-531`) and `_llm_combat` (`:1131-1133`) check
only `tidx < len(enemies_alive)`; a model returning `-1` Python-negative-indexes to
the last alive enemy instead of being treated as invalid.
**Fix:** `tidx < 0` → fall back to first alive (consistent with the existing
out-of-range fallback). Regression test.

### H3. Turn-level: parse failures count as LEGAL plays
On parse failure `llm_sequence=[]` → `_simulate_play_sequence` returns
`legal=True` → `legal_rate` is inflated by exactly the parse-failure rate.
**Fix:** when `parse_ok` is False, score `legal=False`. (Changes `legal_rate`
semantics for models with parse failures — current pilots had parse_ok=1.0 in
turn-level for scout only; llama structured 60% legal column is unaffected because
those were real illegal plays with parse_ok=1.0.) Regression test.

### H4. Synergy parse-failure exclusion policy (document + expose denominators)
Synergy excludes parse-fail samples from all three accuracies (`None`) while
turn-level scores parse failures as 0 — a flaky model gets synergy accuracy
computed only over its parseable samples. Currently moot (parse_ok=1.0 everywhere)
but it would bias cross-model comparison.
**Decision:** KEEP the exclusion (synergy accuracy = knowledge conditional on a
parseable answer; parse_ok_rate is reported alongside), but make the denominators
visible: add `card_pick_n_scored` and `removal_n_scored` to the summary (archetype
already has `archetype_n_scored`), and document the policy in `docs/design.md`.

### H5. k-sampling plan collides with overwrite-by-seed filenames
The roadmap's `--temperature 0.7` k≥5 repeats: re-running the same command
overwrites `results/<model>_<fmt>_seed<N>.json` every repeat; `--seeds 42 42 42 42
42` also collides per-seed files (only the in-memory aggregate survives).
**Fix:** add `--run-tag <s>` CLI option appended to the output stem (default empty
= exactly today's filenames). Unblocks the planned error-bar run.

### H6 (doc). Recommended seeds are ≡ each other mod 20
`--seeds 42 142 242 342 442` → all synergy base seeds ≡ 2 (mod 20): every seed sees
the identical fixture sequence; the multi-seed std measures offer-rotation pairing
(+ sampling at temp>0) only. This is the documented post-fix design, but note it in
`docs/roadmap.md` so the std isn't over-interpreted.

### H7 (minor). `_safe_int` float/string asymmetry
`best_card_index: 1.7` truncates to 1 (scored as 1); `"1.0"` fails `int()` → -1
(scored wrong). Optional: parse float-strings via `int(float(v))`.

### H8 (minor). Archetype substring matching
`"blockade"` would count as a mention of "Block". Optional hardening: word-boundary
regex match. No observed impact in saved samples.

### H9 (trivial). Mock LLM scripted removal answer is "Defend"
`run_benchmark.py:32` — mock pipeline scores removal wrong by script. Switch to
"Strike" so mock runs show a clean all-correct synergy path.
